# 決策模型

日期：2026-11-03　目前版本：**v1**　程式：`scripts/train_decision_model.py`、`scripts/calibrate_stance.py`、`scripts/predict_decision_model.py`、`scripts/compare_model_cells.py`

這是一個中文編碼器，用 LLM 陪審團的標註訓練，每個標註問題對應一個分類頭。訓練好之後，用它免費標註其餘所有抽樣文章（研究設計方法 C）。

- 基底：`ckiplab/bert-base-chinese`，最長 512 字，訓練 3 輪
- 訓練資料：13,920 篇新聞與政黨新聞稿，都有 `gemini-3.8-flash` 的標註。依文章編號切分：訓練 11,106、驗證 1,342、測試 1,472
- robots.txt 標示 `ai-train=no` 的來源（中央社、PTT）不放入訓練資料，但可以用模型標註
- v1 相對 v0 的改動：
  - 依「媒體 × 時期」平衡抽樣，權重取 1/√篇數
  - 立場類別加權
  - 每個分類頭以驗證集做溫度校準
  - 立場分數做反向量尺校準（見下文）

## 立場量尺校準

立場以 5 類機率的期望值輸出（−2 到 +2）。期望值會被壓向中間，而且老師標籤本身有雜訊，模型也學不到全部，所以原始分數的斜率小於 1。

在驗證集上，對每個政黨擬合「模型分數 = c + d × 老師分數」，再反解成「校正分數 = (模型分數 − c) / d」。這個做法能同時消除偏移和壓縮。

一開始的做法反過來：用模型分數去預測老師分數。那樣得到的是最小化逐篇誤差的對應，本質上會往平均回歸、把分布壓得更窄，所以斜率反而變小。這一版已改正。

反向校準的代價是逐篇誤差變大。不過網站與報告用的是「媒體 × 時期」格子的平均，每格有數百篇，逐篇雜訊會被平均掉。

## 全量推論：媒體 × 時期格子

v1 標註了所有已收集的文章：最新新聞 25,240 篇、歷史抽樣 88,087 篇。格子取值為「國民黨平均分數 − 民進黨平均分數」，只納入兩黨各至少 30 篇的格子，與老師的同一格比較。比較分兩種：

- 同一批文章：只算老師也標過的文章。這些多數是訓練資料，所以只能檢驗量尺
- 全部文章：算模型判為政治新聞的所有文章，也就是模型實際的用途

## v0 的偏差與原因

v0 用期望值輸出立場，沒有做量尺校準。結果測試集斜率只有約 0.45–0.57，國民黨平均低 0.09、民進黨平均高 0.11，格子整體往負值偏 0.18–0.21。

先前推測的原因是「訓練資料中偏民進黨的媒體較多」，這個推測不正確：訓練資料並沒有被這些媒體主導，而且 v1 加入平衡抽樣後，原始斜率仍只有約 0.8。主要原因是量尺壓縮：期望值輸出會往中間靠，加上老師標籤的雜訊造成衰減。這要靠校準處理，不是靠重新抽樣。v0 已不再使用。

## 使用方式與限制

- v1 的國民黨、民進黨立場可用於格子平均與趨勢（`scripts/fit_trends.py --labels model`）。民眾黨仍用 LLM 標註
- 逐篇分數的雜訊大於 LLM，不適合拿來判斷單篇文章
- 目前只蒸餾單一老師模型。加入其他陪審員後，改用多個模型的機率分布當訓練目標，模型也會一併繼承陪審團較小的偏誤
- 民眾黨需要更多提及它的標註，才能校準
- 模型與模型卡將於 Hugging Face 公開
